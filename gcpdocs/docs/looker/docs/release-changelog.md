The Looker release changelog lets you review rollout updates, new features, bug fixes, and deprecations across previous and current release iterations. Unlike static release notes, the release changelog displays the dynamic, real-time availability status of features on your specific Looker instance.

The release changelog is available on both Looker (original) and Looker (Google Cloud core) instances. All Looker users can access the release changelog regardless of role or permissions.

## Open the release changelog

To open the release changelog, click notifications **Release Changelog** in the top navigation bar.

The **Release Changelog** dialog displays the following information in the header:

  * **Current version** : Shows the exact version running on your Looker instance (for example, `VERSION 26.20.100000000`).
  * **Release Notes link** : Click **Release Notes** arrow_outward to open the [Looker release notes](https://docs.cloud.google.com/looker/docs/release-notes) page. The Looker release notes contain detailed information about each release item.



## Understand changelog entries

The release changelog lists updates in a table that has the following columns:

  * **VERSION** : The release iteration in which the change was introduced (for example, `26.16.8` or `26.16.0`).
  * **CHANGE** : A summary description of the feature, enhancement, or bug fix.
  * **TAGS** : Functional area chips that categorize the change (for example, `general`, `explore`, `dashboards`, `admin`, `billing`, `ide`, `modeling`, `schedules`, `system_activity`, or `visualization`).
  * **CHANGE TYPE** : The type of change, as follows: 
    * `FEATURE`: A new feature or enhancement.
    * `BUG FIX`: A resolution for a defect or unexpected behavior.
    * `DEPRECATION`: A deprecation or removal of legacy functionality.
  * **STATUS** : The availability of the change on your Looker instance, as follows: 
    * `Available`: The feature or fix is active and available for use on your instance.
    * `Coming Soon`: The change will be arriving as part of a release iteration, but isn't available for use yet on your instance.



## Search and filter changes

You can find specific changes in the release changelog by searching or filtering as follows:

  * **Search by keyword** : Enter text in the **Search** field to filter changes that match your keywords.
  * **Filter by tag, change type, or status** : Click any tag chip, change type badge, or status value in the table to filter the list. Only one chip filter applies at a time. To clear a chip filter, click the active chip again.
