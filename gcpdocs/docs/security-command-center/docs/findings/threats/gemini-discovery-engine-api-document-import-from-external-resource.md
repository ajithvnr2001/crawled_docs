This document describes a threat finding type in Security Command Center. Threat findings are generated by [threat detectors](https://docs.cloud.google.com/security-command-center/docs/concepts-security-sources#threats) when they detect a potential threat in your cloud resources. For a full list of available threat findings, see [Threat findings index](https://docs.cloud.google.com/security-command-center/docs/threat-findings-index).

## Overview

An attempt was made to import documents into a Gemini Enterprise datastore from an external Google Cloud resource outside of your organization or project, such as an external Cloud Storage bucket or BigQuery dataset. Findings are classified as **Medium** severity by default.

[Event Threat Detection](https://docs.cloud.google.com/security-command-center/docs/concepts-event-threat-detection-overview) is the source of this finding.

## How to respond

To respond to this finding, do the following:

### Step 1: Review finding details

  1. Open the `Impact: Gemini Discovery Engine API Document Import from External Resource` finding as directed in [Reviewing findings](https://docs.cloud.google.com/security-command-center/docs/how-to-investigate-threats#reviewing_findings). The details panel for the finding opens to the **Summary** tab.

  2. On the **Summary** tab, review the information in the following sections:

     * **What was detected** , especially the following fields: 
       * **Principal email** : the email address for the user, service account, or AI agent that initiated the document import.
       * **Method name** : the API method that was called (`google.cloud.discoveryengine.v1.DocumentService.ImportDocuments`).
     * **Affected resource** : 
       * **Resource full name** : the full resource name of the project, folder, or organization where the Gemini Enterprise datastore resides.
     * **Related links** , especially the following fields: 
       * **Cloud Logging URI** : a link to Logging entries.
       * **MITRE ATT &CK method**: a link to the MITRE ATT&CK documentation.



### Step 2: Check logs

  1. On the **Summary** tab of the finding details panel, click the **Cloud Logging URI** link to open the **Logs Explorer**.
  2. On the page that loads, look for Gemini Enterprise document import operations using the following filters: 
     * `protoPayload.serviceName="discoveryengine.googleapis.com"`
     * `protoPayload.methodName="google.cloud.discoveryengine.v1.DocumentService.ImportDocuments"`
  3. Inspect `protoPayload.request` to identify the target datastore (`parent`) and the external source resource (such as `gcsSource.inputUris`, `bigquerySource`, `cloudSqlSource`, `spannerSource`, `firestoreSource`, `alloyDbSource`, `bigtableSource`, or `fhirStoreSource`).



### Step 3: Research attack and response methods

  1. Review MITRE ATT&CK framework entries for this finding type: [Data Manipulation: Stored Data Manipulation](https://attack.mitre.org/techniques/T1565/001/).
  2. To develop a response plan, combine your investigation results with MITRE research.



### Step 4: Implement your response

The following response plan might be appropriate for this finding, but might also impact operations. Carefully evaluate the information you gather in your investigation to determine the best way to resolve findings. 

  1. Contact the owner of the project that contains the affected Gemini Enterprise datastore to verify whether the import from the external resource was authorized. If legitimate, configure trusted cross-project resource access or ingest from an internal bucket.
  2. Consider [revoking permissions](https://docs.cloud.google.com/iam/docs/granting-changing-revoking-access#revoking-console) for the principal that initiated the import until your investigation is complete.
  3. Review and purge any unauthorized or untrusted documents imported into the Gemini Enterprise datastore to prevent knowledge store poisoning or indirect prompt injection.
  4. To prevent data movement across organizational boundaries, configure [VPC Service Controls service perimeters](https://docs.cloud.google.com/vpc-service-controls/docs/overview) around your Gemini Enterprise and storage resources.



For response recommendations, see [Respond to AI threat findings](https://docs.cloud.google.com/security-command-center/docs/respond-ai-threats).
