Hoy lanzamos ocho novedades importantes que reúnen tus registros, seguimientos, análisis, alertas, paneles de control y la exportación de datos en una[ _única plataforma de observabilidad_](https://developers.cloudflare.com/observability/), con una estructura de precios más sencilla y predecible.

**Aquí están las novedades:**

  * Un lugar para explorar los registros de toda la red de Cloudflare
  * Seguimiento de extremo a extremo desde el perímetro de Cloudflare hasta tu origen
  * Una API SQL unificada para consultar los datos de Cloudflare
  * Un único modelo de precios para los datos de observabilidad recopilados y almacenados en Cloudflare
  * Alertas personalizadas en tus datos de observabilidad
  * Todos los análisis de tu dominio en un solo lugar, con 30 días de retención de datos
  *  _Paneles personalizados creados a partir de tus datos de observabilidad_
  * Exporta tus datos con Logpush, ahora disponible en los planes de autoservicio



## **Una única plataforma de observabilidad para todo Cloudflare**

A menudo, para entender un problema se necesitan datos de más de un producto de Cloudflare. Un pico en las respuestas 5xx podría deberse a un Worker, a tu origen o a que Cloudflare no consiga conectarse a tu origen a nivel global o regional. Pero investigarlo hoy en día requiere saber qué producto es el responsable de cada señal y cómo consultarlo.

Observability debería ser una capacidad de toda la plataforma: debería reflejar cómo se comportan realmente las aplicaciones y ofrecerte todo el contexto necesario para resolver un problema. En los próximos meses, verás cómo más productos, conjuntos de datos y flujos de trabajo de Cloudflare pasan a formar parte de esta plataforma de observabilidad compartida, con precios, experiencias de producto y funciones más coherentes. Estas ocho novedades son el primer paso hacia una observabilidad más unificada.

## 1\. **Analiza todos tus registros desde una ubicación centralizada**

La[ _nueva página de inicio de Logs_](https://developers.cloudflare.com/observability/logs/)combina[ _Workers Observability_](https://developers.cloudflare.com/workers/observability/) (para depurar aplicaciones de Workers y sus recursos conectados) con[ _Log Explorer_](https://developers.cloudflare.com/log-explorer/)(para buscar en los registros de seguridad). Ahora puedes elegir entre conjuntos de datos de registros como eventos HTTP, eventos de firewall, Workers, contenedores, R2 y AI Gateway, y usar las mismas herramientas y capacidades de investigación para cada uno.

Empieza por un aumento en la latencia de las solicitudes, agrúpalas por nombre de host o centro de datos, filtra los resultados a las rutas afectadas e inspecciona las solicitudes individuales por Id. de rayo. Si la investigación te lleva a otro producto de Cloudflare, cambia los conjuntos de datos sin salir de Logs. Próximamente admitiremos la realización de consultas en varios conjuntos de datos, lo que te permitirá conectar eventos relacionados en todos los productos en una sola consulta.  
  
Puedes consultar tus registros con SQL sin procesar o con filtros integrados para centrarte en eventos específicos. Crea visualizaciones con lenguaje natural y analiza e identifica fácilmente anomalías detectadas.

## 2\. **Realiza un seguimiento de las solicitudes a lo largo de toda nuestra plataforma — ahora en fase beta abierta**

Hemos lanzado[ _Cloudflare Traces en fase beta abierta_](http://blog.cloudflare.com/cloudflare-tracing), lo que te ofrece una vista a nivel de solicitud de las reglas de seguridad compatibles, las transformaciones, las decisiones de caché, el enrutamiento, los Workers y la gestión del origen. Puedes ver cómo se movió tu tráfico a través de nuestra plataforma y conectar los puntos entre la configuración de Cloudflare y la influencia que esto tiene en el tiempo de procesamiento de solicitudes, las decisiones de enrutamiento y más.

[_Establece una tasa de muestreo de referencia_](https://developers.cloudflare.com/observability/traces/configuration/) para obtener visibilidad continua, luego usa[ _Reglas de seguimiento_](https://developers.cloudflare.com/observability/traces/configuration/#trace-rules) para capturar tráfico específico a una tasa mayor durante una investigación. Elige nombres de host, rutas, direcciones IP o encabezados, busca por[ _Id. de rayo_](https://developers.cloudflare.com/fundamentals/reference/cloudflare-ray-id) e inspecciona los tramos resultantes directamente en el panel de control de Cloudflare.

Puedes exportar los seguimientos mediante[ _OpenTelemetry_](https://opentelemetry.io/), mientras que la[ _propagación del contexto del seguimiento de W3C_](https://www.w3.org/TR/trace-context/) permite aceptar un contexto de seguimiento entrante y transmitirlo a tu origen. Echa un vistazo a[ _entrada completa del blog para saber más sobre Cloudflare Tracing_](http://blog.cloudflare.com/cloudflare-tracing) o ejecuta este comando en tu agente para empezar:

## 3\. **Haz que tu agente consulte los datos de observabilidad con una API SQL unificada**

Además, los agentes necesitan una forma coherente de analizar tus datos de observabilidad, investigar problemas, correlacionar señales y verificar soluciones. Hemos lanzado[ _una API SQL unificada_](https://developers.cloudflare.com/analytics/sql-api/), ahora en fase beta, para consultar la telemetría en todo Cloudflare. En lugar de integrarse por separado con los registros de Workers, los eventos de seguridad de los contenedores, los registros de solicitudes HTTP y los datos de análisis, las usuarios y los agentes pueden consultarlos usando un solo dialecto SQL, modelo de autenticación y API.

Tu agente puede utilizar la nueva[ _CLI de Cloudflare_](https://blog.cloudflare.com/cloudflare-cf-cli-launch/), cf, para buscar y ejecutar consultas desde la línea de comandos o conectarse a través del servidor de[ _MCP Observability de Cloudflare_](https://github.com/cloudflare/mcp) para investigar registros, seguimientos y análisis.[ _Los esquemas de conjuntos de datos, los campos y las consultas de ejemplo_](https://developers.cloudflare.com/analytics/sql-api/datasets/) están disponibles para ayudar tanto a los usuarios como a los agentes a crear consultas.

Además, también vamos a integrar la interfaz SQL directamente en Workers con un [_enlace nativo._](https://developers.cloudflare.com/workers/runtime-apis/bindings/analytics-sql/) Tu Worker ahora puede hacer cosas como consultar datos de[ _Analytics Engine_](https://developers.cloudflare.com/analytics/analytics-engine/) para medir el uso de los clientes e impulsar los flujos de trabajo de facturación, crear paneles de análisis para los clientes, generar informes de estado o automatizar la investigación de incidencias sin tener que configurar un cliente API independiente.

## 4\. **Nuevos precios para todos los registros y seguimientos capturados y almacenados**

Para todos los registros y seguimientos capturados y almacenados en Cloudflare, vamos a pasar a una única suscripción y estructura de precios unificada de Observability. A partir del **1 de diciembre de 2026** , este modelo de precios se aplicará a todos los planes (con efecto a partir de la renovación para todos los clientes Enterprise) y abarcará los registros existentes de la Plataforma para desarrolladores, incluidos Workers, Contenedores y AI Gateway, así como todos los datos de seguimiento.

Dado que los registros y los seguimientos pueden variar drásticamente de tamaño, el nuevo modelo se basa en el **volumen que capturas y almacenas** en lugar de en un recuento basado en eventos. Este ajuste de precios será. Consulta nuestra[ _documentación_](https://developers.cloudflare.com/observability/pricing/)para conocer más detalles sobre los precios.

## 5\. **Configura alertas personalizadas en tus datos de observabilidad, ya en fase beta**

Las notificaciones ([_ahora llamadas "Alertas"_](https://developers.cloudflare.com/notifications/)) acaban de recibir una importante actualización. Ahora puedes definir alertas personalizadas directamente sobre cualquier elemento compatible con nuestra nueva API SQL unificada, incluidos los registros de solicitudes HTTP, los eventos de Workers, los conjuntos de datos de Workers Analytics Engine, los conjuntos de datos analíticos, los seguimientos y los eventos de seguridad.

Elige un conjunto de datos en el panel de control o define la condición mediante SQL personalizado. A continuación, selecciona un umbral, una anomalía o un SLO, configura la ventana de evaluación y elige dónde debe enviarse la alerta. Puedes configurar una alerta cuando las respuestas 5xx de origen superen un umbral durante cinco minutos, un contenedor falle repetidamente, los errores de Worker aumenten tras una implementación o la latencia de los rastros supere un límite esperado. 

Puedes enviar alertas directamente a las herramientas que tus equipos ya utilizan, como herramientas de gestión de incidencias, plataformas de chat y webhooks. Los [  _webhooks ya están disponibles en todos los planes_](https://developers.cloudflare.com/notifications/get-started/configure-webhooks/), lo que te permite redirigir las alertas a servicios personalizados o incluso a tu agente para que comience a investigar de inmediato. ## 6\. **Consulta el análisis de tu dominio en un solo lugar — ahora con 30 días de retención**

Entender lo que está sucediendo en tu dominio a menudo significaba recopilar métricas de diferentes productos de Cloudflare. Estamos reuniendo datos de tráfico, rendimiento, seguridad, caché, origen y DNS para que puedas ver cómo se relacionan entre sí. Si la latencia aumenta, puedes ver rápidamente si está vinculada a un centro de datos, nombre de host u origen específico de Cloudflare.

Además, ahora obtienes[ _30 días de análisis de dominios en todos los planes._](https://developers.cloudflare.com/analytics/account-and-zone-analytics/zone-analytics/) Un mes completo de historial te da tiempo para investigar los problemas después de que se produzcan, comparar el día de hoy con el mismo día de semanas anteriores y distinguir entre un pico puntual y una tendencia más prolongada.

## 7\. **Crea paneles de control personalizados**

Los paneles preconfigurados cubren los casos de uso más comunes, pero las aplicaciones suelen utilizar varias partes de Cloudflare. Con los[ _paneles personalizados_](https://developers.cloudflare.com/analytics/custom-dashboards/), puedes reunir en una sola vista los datos analíticos de todo Cloudflare, los registros y las seguimientos de la plataforma Workers, y los eventos de seguridad. Haz un seguimiento del volumen de solicitudes, los errores, la latencia, el almacenamiento y el tráfico bloqueado, y luego comparte el panel con tu equipo. En lugar de volver a crear consultas durante cada investigación, tienes un lugar donde supervisar las señales que importan para tu aplicación.

## 8\. **Logpush ya está disponible en todos los planes de autoservicio**

[ _Logpush_](https://developers.cloudflare.com/logs/logpush/), que antes solo estaba disponible para el plan Enterprise, ahora está disponible en todos los planes de autoservicio, lo que te permite exportar todos los registros de Cloudflare a las herramientas y destinos que ya utilizas. ¿Necesitas aplicar filtros, ocultar información, enriquecer eventos o modificar los resultados antes de su entrega?[ _Transformers_](https://developers.cloudflare.com/logs/logpush/transformers/) ya está disponible de forma general, lo que te permite aplicar cualquier transformación SQL sin necesidad de utilizar un proceso ETL independiente.  
  
Presentamos[ _el modelo de precios basado en el uso_](https://developers.cloudflare.com/changelog/post/2026-09-30-logpush-usage-based-pricing/) para Logpush y Transformers. Cada uno incluye una cuota mensual gratuita, con precios sencillos para el uso adicional:

Uso de exportación| Incluido cada mes| Uso adicional  
---|---|---  
Exportaciones a destinos de Cloudflare| 25 GB| 0,03 USD/GB  
Exportaciones a destinos externos| 25 GB| 0,10 USD/GB  
Logpush Transformers| 1 GB| 0,04 USD/GB  
  
Consulta la[ _documentación_](https://developers.cloudflare.com/logs/logpush/) para comenzar con Logpush y ver los detalles completos sobre los precios.

## **Próximamente:**

  * **Mayor retención de tus datos de observabilidad:** podrás conservar los datos de registro y seguimiento hasta un año, lo que facilitará la investigación de problemas recurrentes, la comparación del comportamiento histórico y el análisis de tendencias a largo plazo.
  * **Compatibilidad con la API de OpenTelemetry en Workers:** seguiremos ampliando nuestras API de OpenTelemetry para que puedas añadir atributos a los spans existentes u obtener el contexto de los seguimientos.
  * **Exportación más sencilla de métricas con OpenTelemetry:** podrás enviar métricas de Cloudflare a destinos compatibles con OpenTelemetry y analizarlas junto con la telemetría del resto de tu pila.
  * **Los nuevos precios entrarán en vigor el 1 de diciembre de 2026:** si ingestas o almacenas datos de observabilidad en Cloudflare, se te aplicará el plan de precios unificado en función de tu uso. Te avisaremos antes de que entre en vigor el cambio.



## **¿Listo para empezar a investigar?**

Entendemos que a veces Cloudflare pueda parecer una caja negra. Estas actualizaciones son solo el principio para mostrar lo que está pasando, hacer accesibles los datos subyacentes y darte el contexto que necesitas para actuar. Esa transparencia cobra aún más importancia ahora que los agentes pasan de escribir software a gestionarlo. Un agente solo puede cerrar el ciclo entre un cambio y su resultado si puede consultar qué ha pasado, identificar el fallo y verificar la solución.

Al basarnos en[ _OpenTelemetry_](https://opentelemetry.io/),[ _W3C Trace Context_](https://www.w3.org/TR/trace-context/) y SQL, nos comprometemos a ofrecerte a ti y a tus agentes interfaces estándar y portátiles para acceder a ese contexto. Echa un vistazo a nuestra nueva página de inicio de la[ _documentación de Observability_](https://developers.cloudflare.com/observability/)para obtener más información.
