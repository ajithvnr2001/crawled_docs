# Forge のご紹介：SDK、CLI、ドキュメントなどを生成するオープンソースパイプライン

![Dimitri Mitropoulos](https://blog.cloudflare.com/_image?href=https%3A%2F%2Fblog.cloudflare.com%2F_emdash%2Fapi%2Fmedia%2Ffile%2F01KW498DEF6RX03R0G7TNW7CR3.webp&w=64&h=64&f=webp&fit=cover&position=center)![Matt “TK” Taylor](https://blog.cloudflare.com/_image?href=https%3A%2F%2Fblog.cloudflare.com%2F_emdash%2Fapi%2Fmedia%2Ffile%2F01KW46YW143XXGWD5TFT0BBYBQ.webp&w=64&h=64&f=webp&fit=cover&position=center)![Samuel Macleod](https://blog.cloudflare.com/_image?href=https%3A%2F%2Fblog.cloudflare.com%2F_emdash%2Fapi%2Fmedia%2Ffile%2F01KW498X1ZVM0N111DBDKB3MM1.jpg&w=64&h=64&f=webp&fit=cover&position=center)

本日、SDK、CLI、ドキュメント、ライブラリを生成するための新たなアプローチとして、[Forge](https://github.com/cloudflare/forge)をご紹介します。Forgeは、誰でも無料でデプロイして実行できる、オープンソースのプラガブルな生成パイプラインです。

Forgeはまだ開発の初期段階ですが、すでに[cf CLI](https://blog.cloudflare.com/cloudflare-cf-cli-launch/)に必要な成果物を生成しています。今後数か月のうちに、CloudflareのAPIドキュメントやSDKなどもForgeで生成する予定です。

Forge を構築したのは、エージェントをお客様として扱うために、私たち自身が必要としていたからです。そして今回オープンソース化するのは、エージェントが必要とするあらゆる利用手段を、誰もが生成できるべきだと考えているためです。以前は、CLI、API SDK、MCP サーバーと、それらに対応する優れたドキュメントが必要なのは開発者向け製品だけでした。今では、どのような製品にも欠かせない基本要件となっています。

## **API が既存のジェネレーターで対応できる規模を超えた**

Cloudflare API には3,500を超える操作があり、それらを支える数百のサービスは、Rust、Go、TypeScript、Python など、さまざまな言語で記述されています。Cloudflare API 全体に対応する CLI、SDK、API ドキュメントの構築に着手するにあたり、この規模を処理できるコード生成パイプラインが必要でした。また、使用言語や各エンジニアリングチームの作業方法の違いに対応できる、十分な柔軟性も必要でした。

チーム間の調整にかかる負担を減らす仕組みも必要でした。Cloudflare の各プロダクトチームが API を変更する場合、その変更をマージしてお客様に提供する前に、変更後に生成される Cloudflare 全体の CLI、SDK、ドキュメントサイトをプレビュービルドで確認できなければなりません。また、変更によって生成パイプラインを誤って破損しないようにする仕組みも必要です。さらに、SDK だけでなく、Cap'n Web や MCP なども生成できるよう拡張可能なシステムが必要でした。

![](data:image/bmp;base64,Qk32BAAAAAAAADYAAAAoAAAACAAAAAgAAAABABgAAAAAAMAAAAATCwAAEwsAAAAAAAAAAAAAe3x7aWxqSlNRanNypqyrys7OzdDPuLq5hYOCfHt5c3Rzi46NtLa1zc7OysvKtLOzjYmHjIiHko+Np6WkwcC/zszMxcPCraqpj4mIk46NoZ2ctrKxx8TDy8fHvLm4pJ+eiISDkIuKop6dt7OyxMC/w7++sq6tmZWUenp4g4KAmJWUrqqpura1uLW0p6Skjo2MbG9tdXd1iomIoZ6dr6yrr6yrnp6dhoiHZWpobnFwhISDm5mYqqemqqmom5uag4aF)![](https://blog.cloudflare.com/_image?href=https%3A%2F%2Fblog.cloudflare.com%2F_emdash%2Fapi%2Fmedia%2Ffile%2F01M3J4EPCB6S3BJ6C7BY6HKZKN.png&w=715&h=640&f=webp&fit=cover&position=center)

何百ものリポジトリにわたって、すべてのプルリクエストのプレビューを生成するものが必要でした。

この問題の解決を目指す複数のホスト型製品を試し、一部は本番環境でも利用しました。しかし、どれも私たちの問題を解決できず、サービス自体が終了したものもあります。あるチームが生成パイプラインを壊す変更を誤ってマージし、別のチームがリリース時に問題を発見することもありました。自分たちでは制御できないホスト型ツールをさかのぼって原因を調べ、チーム間やベンダーとの変更調整に多くの時間を費やしていました。

こうして私たちは Forge の構築を始めました。

Forge は、こうした問題をすべて解決することを目指しています。AI コードレビュアーやテストパイプラインと同じように、各チームの API リポジトリの CI 上で実行されます。すべての変更をリントし、変更箇所だけを強調した CLI、ドキュメント、SDK のプレビュービルドを生成するため、実際にインストールしてテストできます。考え方は [Workers Previews](https://blog.cloudflare.com/worker-previews/) と同じです。変更のたびに完全なプレビュービルドを作成する仕組みを、API が数百のサービスやリポジトリに分散している場合も含め、大規模な SDK 生成に適用します。これが Forge の目指すものです。

![](data:image/bmp;base64,Qk32BAAAAAAAADYAAAAoAAAACAAAAAgAAAABABgAAAAAAMAAAAATCwAAEwsAAAAAAAAAAAAAeXOei4atop/CnZu5bW2HAAAAAAAAGTA4hoKel5OsrKq/p6a4enqJAAwmAAAAQElIlZOgo6Kst7a8srG2iIiOQEJLICgqX2JdoKCkrKyuvr67ubm1lZWVYmJoVlZZeXl0pqepsLGxv8C8u7y3n5+ee3qAdnR5joyKp6qwr7K1u729ubq6paWnjo2SjYqPnZqcpqu0rbC5trm/tre8qKitmpiempedp6Onpqq2q6+6tLfAtLa9qamwnpyin5uhqqas)![](https://blog.cloudflare.com/_image?href=https%3A%2F%2Fblog.cloudflare.com%2F_emdash%2Fapi%2Fmedia%2Ffile%2F01M3J4EVDEJ0CVMAT598QFERDT.png&w=715&h=751&f=webp&fit=cover&position=center)

Forgeは、ダウンストリームの問題を引き起こす前に、CIの問題を検出するのに役立ちます。

## **Forge のトランスフォーマーは Cap'n Web をはじめ、あらゆるものを生成できる**

Cloudflare には、一般的な対応言語の枠を大きく超えるジェネレーターを必要とする理由が、他社以上にあります。[Cap'n Web](https://capnweb.com/) は Cloudflare の RPC システムであり、TypeScript からリモート API を、ローカルメソッドと同じ感覚で呼び出せるようにします。
    
    
    // Authenticate, get the user's ID, fetch their profile, and fetch every friend's profile...
    let authed = api.authenticate(apiToken);
    let profile = api.getUserProfile(authed.getUserId());
    let friends = authed.getFriendIds().map(id => api.getUserProfile(id));
    
    // ...in a *single* request
    let [me, myFriends] = await Promise.all([profile, friends]);

Forge を使えば、OpenAPI 仕様から Cap'n Web を直接生成できます。これにより、Workers から他の API へ接続する[バインディング](https://developers.cloudflare.com/workers/runtime-apis/bindings/)を生成できるようになります。実際、Workers ランタイムのバインディングも、RPC メソッドを公開する Workers として実装されています。

これは Cap'n Web に限った話ではありません。すでに利用している一般的なツールにも、同じ仕組みが必要です。たとえば [TanStack Query](https://tanstack.com/query/) を使用している場合、API から直接、アプリケーション用の TanStack Query バインディングを生成できることが理想です。そうすれば、常に最新の状態を保ち、実際の API に対して検証できます。Zod や Valibot のスキーマ、MCP サーバーなど、API を利用しやすくするあらゆるものを生成する場合も同様です。

これが可能なのは、Forge のコードジェネレーターが柔軟に設計されており、ある出力から次の出力へ情報を受け渡せるためです。

![](data:image/bmp;base64,Qk32BAAAAAAAADYAAAAoAAAACAAAAAgAAAABABgAAAAAAMAAAAATCwAAEwsAAAAAAAAAAAAAl5eXl5eXmJiYm5ubnZ2dnZ2dm5ubmJiYlZWVlZWVlpaWl5eXmJiYmZmZmJiYl5eXk5OTk5OTk5OTk5OTk5OTlJSUlJSUlJSUkpKSkZGRkZGRkZGRkpKSk5OTk5OTkpKSkJCQkJCQkZGRk5OTlZWVlpaWlZWVkZGRkJCQkJCQkpKSl5eXnJycnZ2dmJiYkJCQj4+PkJCQk5OTmpqaoqKio6OjnJyckJCQj4+PkJCQlJSUnJycpKSkpqamnp6ekJCQ)![](https://blog.cloudflare.com/_image?href=https%3A%2F%2Fblog.cloudflare.com%2F_emdash%2Fapi%2Fmedia%2Ffile%2F01M3J4ERXXG0DDMKKETZXQQHHX.png&w=715&h=757&f=webp&fit=cover&position=center)

オリジナルのOpenAPI定義はTypeScript SDKに組み込まれており、cf CLIおよびCap'n Web仕様を生成するために使用されます。

## **Forge のトランスフォーマーは連結可能：別の出力から新たな出力を生成**

Forge はプラグインで拡張できるよう設計されており、さまざまな入出力形式に対応します。Forge には CLI、SDK、ドキュメント用のジェネレーターが用意されていますが、特定のライブラリ向けパッケージや、ダッシュボード、アプリケーション全体を生成するトランスフォーマーを追加することもできます。現在の入力形式は OpenAPI ですが、将来的には [AsyncAPI](http://asyncapi.com)、GraphQL、Cap'n Proto、Protobuf などにも対応できる設計になっています。

これは、単に互換性を確保するだけの仕組みではありません。生成ターゲットを連結し、あるターゲットの出力から別のターゲットを生成できます。他のジェネレーターでも、Go SDK から CLI や Terraform 向けの成果物を生成する方法は一般的です。しかし、従来不足していたのは、こうした連結方法を利用者自身が制御する仕組みです。Forge はそれを提供します。

![](data:image/bmp;base64,Qk32BAAAAAAAADYAAAAoAAAACAAAAAgAAAABABgAAAAAAMAAAAATCwAAEwsAAAAAAAAAAAAA3NjY3dra3t3e4OHi4OLj4OHi4N/g4N3e1dHR19TU3NnZ4d/f5OHi4uDg39zc29jYzsrJ0c3M2tXU4tzc5uDf5N7e3djY1tLRyMTDzMjH1tDP4dnY5t7d5Nzb29XU0s7Nx8TDysfG087N3dbV4tva4NrZ2dTT0c3NycfHy8nJ0c7O19PT29jX3NjY2NXV0tDQzcvMzcvNz87P0tLS1dXW19fX1tbW1NPUzszOzs3Ozs7P0NHS09XV1dbX1tbX1dTW)![](https://blog.cloudflare.com/_image?href=https%3A%2F%2Fblog.cloudflare.com%2F_emdash%2Fapi%2Fmedia%2Ffile%2F01M3J4EQPM3GPCFH9MW0W9W0AB.png&w=715&h=795&f=webp&fit=cover&position=center)

Forgeは、ターゲットを連鎖させて新しい出力を生成することができます。

私たち自身にも、この仕組みが必要でした。cf CLI は TypeScript で記述されていますが、一般的な SDK ジェネレーターでは、CLI を生成する際に TypeScript SDK を生成元として連結することはほとんどありません。しかし、この状況から、より本質的な問題に気づきました。SDK ジェネレーターが、利用者に代わって生成元の言語を決める必要があるのでしょうか。Python を中心に使用する組織なら、CLI も Python で作りたいかもしれません。

「自動生成されるコードなら、Python かどうかは関係ないのでは」と思うかもしれません。しかし、CLI は事情が異なります。CLI には、SDK では意味を持たないローカル専用の動作が追加されることがよくあります。こうした動作は API 呼び出しに対応するものではないため、手作業で実装します。たとえば cf CLI には、生成された機能に加えて cf dev や cf build などのコマンドがあります。これらのコマンドからは、Vite など、他のパッケージの TypeScript API を呼び出す必要があります。

さらに、ドキュメントも考えてみましょう。CLI とドキュメントを OpenAPI 仕様だけから生成している場合、手作業で追加したコマンドをドキュメントへ取り込み、他のコマンドと同じように掲載するにはどうすればよいでしょうか。

現在、この処理を実現できる既存のツールは見つかりませんでした。しかし、これはまさに cf に必要な機能です。そのため、Forge に組み込むことにしました。

## **利用者に影響を与えずに API を変更**

Forge は、API のバージョン管理を改善するための基盤にもなります。Cloudflare の v4 API は、10年間にわたって唯一のメジャーバージョンでした。その間、新しいメジャーバージョンを公開していないように見えますが、SemVer の定義に照らせば、新しいメジャーバージョンに相当する変更を何度も行っています。一方、API の一部の操作には、製品が該当するライフサイクル段階をとうに終えているにもかかわらず、内部的な「v2」タグや「beta」識別子が残っています。

v4 API を長年提供してきたからこそ、新しい v5 へ一斉に移行すれば、多くのお客様が取り残されることを十分に理解しています。そこで、Forge で各段階の成果物を生成しながら、既存のクライアントや SDK を壊すことなく新しいメジャーバージョンを公開できる API バージョン管理の手法に取り組んでいます。

TypeScript、Rust、Python、Go、PHP、Terraform などの SDK については、近いうちに詳しくお伝えします。なかでも Terraform は重要です。Terraform プロバイダーのアップグレードには特有の厳密な検証が必要であることを理解しているため、Terraform の移行には特に細心の注意を払います。

## **重要なツールはすべての人に開かれているべきだ**

API 向けのツールを構築することは、インターネットを支える中核的な要素であり、SaaS 製品に依存せずに実現できるべきだと考えています。SDK、CLI、ドキュメントは利用者自身が所有すべきものです。また、それらを生成した後は、場所や用途を問わず、無料で自由に利用できるべきです。

そのため、[Forge を制約の少ない](https://github.com/cloudflare/forge) Apache 2.0 ライセンスの下でオープンソースとして提供します。ぜひこの取り組みに参加し、貢献していただきたいと考えています。

もちろん、参加しなくても構いません。すべてを自分たちだけで利用したい場合も、ご自由にどうぞ。Forge は、独自の変更を加えたうえで、あらゆる目的に無料で非公開のまま実行できます。
