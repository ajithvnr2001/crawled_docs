今日は、Cloudflare Monetization Gatewayをクローズドベータとして提供開始し、すでに本番稼働している4つの顧客ユースケースをご紹介します。3か月前に[ _計画を発表_](https://blog.cloudflare.com/monetization-gateway/)して以来、顧客と緊密に連携しながら、Gatewayを高速かつ柔軟で使いやすいものに仕上げてきました。

わずか数クリックで、Monetization Gatewayは、ドメインオーナーがエージェントにWebサイト、API、MCPツール、またはデータセットへのアクセスを課金可能にします。今すぐ[ _Cloudflare Dashboard_](https://dash.cloudflare.com/?to=/:account/monetize/monetization-gateway)からアクセスをリクエストしてください。

### **エージェントの急増とマシン決済の拡大**

現在、ほとんどのソフトウェア企業はサブスクリプションまたはプリペイドクレジットで製品を販売しています。こうしたビジネスモデルでは、購入者に相当な初期投資が求められるため、予算に合わせた少数のサブスクリプションに限定されます。しかし、このビジネスモデルは、インターネットトラフィックの主役であるエージェントの動作様式とは合致していません。

エージェントは結果を求めます。それは直接的な質問であれ、暗黙的な要求であれ同様です。結果を達成するために、エージェントは新しいサイトを訪問し、MCPツールを呼び出し、データフィードを取り込む場合があります。世界中の企業が、エージェントのより良い結果を支援する重要な経路に位置したいと考えています。これにより、新しいユーザーがいる場所でリーチし、エージェントの回答への貢献に対して報酬を得て、ヘッドレスエージェントコマースでリーダーポジションを確立できます。

この機会を活かすには、企業がビジネスモデルをエージェントの消費パターンに合わせる必要があります。支払いはエージェントの消費単位（リクエスト単位、検索クエリ単位、トークン単位）と一致している必要があります。現在の一般的な決済インフラはこれに対応できていません。これらの決済インフラは、購入者が高レイテンシを受け入れ、大きな金額でのみ取引し、販売者に既知または識別可能なエンティティであることを前提としています。エージェントが求めるのはその逆、すなわち安価で高速かつ信頼性の高い決済インフラであり、最小限の人間の介入で安全にスケールできるものです。

販売者と購入者は消費に基づいたビジネスモデルへの転換を促され、それを実現する決済ネットワークを活用するようになるでしょう。現在、ステーブルコイン取引とその基盤となるブロックチェーンネットワークはこの要件に対応できています。将来的には、既存のネットワークがソリューションを導入したり、新しい決済ネットワークが登場したりする可能性があります。Monetization Gatewayは、販売者が自社製品に集中でき、購入者が予測可能な購買体験を得られるよう支援するために存在します。

### **Monetization Gatewayで構築する**

Monetization Gatewayを使えば、販売者はCloudflareのネットワーク背後にあるあらゆるリソースに対し、利用ごとの課金でエージェントに請求できます。APIやツール、データなど、リクエスト自体が利用となるリソースに最適化されています。高価値コンテンツは異なります。ページが1度クロールされ、1,000回利用されることもあります。そのような場合には、[ _Pay Per Use_](http://blog.cloudflare.com/pay-per-use)が検証済みの信頼できる購入者ネットワークを提供し、各利用を報告・支払いします。

Gatewayは、HTTP 402 Payment Requiredステータスコードを使用することで、購入者がリソースへのアクセスと同時にHTTPを通じて支払いを提示できるようにします。チェックアウトページへのリダイレクトも、別途決済APIの呼び出しも不要という点が重要な違いです。

販売者は、どのリクエストに支払いが必要か、コスト、および支払い先を定義します。購入者は支払い指示を受け取り、承認に署名し、支払い決済後にリソースを受け取ります。

最もシンプルな形では、これを「エージェント向けペイウォール」と考えることができます。販売者は数秒、数クリックで公開でき、課金対象のオーディエンスを特定し、支払いが完了するまで購入者がリソースにアクセスできないようにできます。

実装の容易さに加え、販売者にはすぐに使える豊富な価格設定・収益化機能を提供します。URLやヘッダー、クエリパラメータなどリクエストのあらゆる部分に対応する価格ルールを作成し、複数の価格スキームから選択できます。残りの処理はすべて当社が担当します。具体的には、[ _Coinbase x402 Facilitator_](https://docs.cdp.coinbase.com/x402/seller/facilitator)を通じた支払いの検証と決済、障害とリトライ、アナリティクス、x402プロトコルの変更への対応です。支払いは米ドルに連動したステーブルコインのUSDCを使用して[ _Base_](https://www.base.org/)ブロックチェーン上で決済されます。今後、販売者のサービスをエージェントが発見できるようにする支援、全取引のログ公開、追加の決済インフラへの対応、アイデンティティプリミティブの組み込みを計画しています。

### **Cloudflare AI Gateway：推論への支払い**

[ _CloudflareのAI Gateway_](https://www.cloudflare.com/products/ai-gateway/)は、開発者が単一のAPIキーで数百のAIモデルにアクセスできるコントロールプレーンおよびモデルマーケットプレイスです。エコシステム内で最も豊富なモデルカタログを運営し、できるだけ多くの顧客に届けることが目標です。AI Gatewayでは、顧客がAI Gatewayの全消費に充当できる[ _クレジットを購入_](https://developers.cloudflare.com/ai-gateway/features/unified-billing/)できます。しかし、エージェントがウォレットを持つケースが増えるにつれ、クレジット残高を唯一の利用手段とすることは不必要な摩擦を生じさせます。

本日より、米国拠点のCloudflareの顧客は、ヘッダー「`PAYMENT-METHOD: x402`」を追加することで、選択されたモデル群へのリクエスト時に推論の支払いが可能になります。詳細な手順は[ _AI Gateway Developer Docs_](https://developers.cloudflare.com/ai-gateway/features/machine-payments/)をご覧ください。将来的には、CloudflareのさらなるインフラストラクチャプロダクトにHTTP 402ステータスコードがネイティブに組み込まれる予定です。
    
    
    $ curl -iX POST "https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/ai/run" \
      --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
      --header "Payment-Method: x402" \
      --header "Content-Type: application/json" \
      --data '{
        "model": "z-ai/glm-4.7-flash",
        "input": {
          "max_tokens": 9001,
          "messages": [
            {
              "role": "user",
              "content": "What is Cloudflare?"
            }
          ]
        }
      }'

AI Gatewayには各トークンの請求方法を制御する複雑な価格エンジンがあります。当社はMonetization Gatewayをオリジン制御型の価格設定要件に対応するよう共同設計しました。この設定が有効な場合、Monetization Gatewayは価格情報を販売者（AI Gateway）から直接取得します。AI Gatewayにとっては、Monetization Gatewayにルールカタログを維持することなく、既存の価格モジュールを活用できることを意味します。

### Ceramic.ai：Web検索への支払い

>  _「Webは人間の買い手のために作られました。サインアップしてカードを入力する人のために。エージェントは自身を代表して行動する必要があり、支払いはその手段です。検索はあらゆるエージェントが最初に必要とするものの1つなので、エージェントが最初に購入できるものの1つであるべきです。」— Dr. Anna Patterson、創業者、[Ceramic.ai](http://Ceramic.ai)_

推論が思考であるなら、検索は現実確認です。[ _Ceramic.ai_](http://Ceramic.ai)はエージェント向けに構築されたWeb検索APIを提供しています。[Ceramic.ai](http://Ceramic.ai)は400億ページ以上の独自インデックスを保有し、マシンコーラー向けにスタックの全層を最適化して、50ミリ秒以内に検索結果を返します。その速度なら、エージェントはタスク全体を通じて繰り返し検索できます。

これにより、検索はエージェントネイティブ決済に自然に適合します。検索はエージェントが購入するものの中でも最も弾力的なものの1つです。単純な質問は1回のクエリで済む場合もありますが、複雑な調査タスクには数百回が必要になることもあります。エージェントが検索に自ら支払えるようになれば、あらかじめ設定された予算に対してクエリを配分する必要がなくなります。タスクに基づいて検索の深度を自ら判断し、証拠がより多く必要な場合には多く支出できます。

[Ceramic.ai](http://Ceramic.ai)はMonetization Gatewayの固定価格収益化スキームを使用し、APIキーなしでエージェントが検索を実行できるようにしています。[ _デモ_ と _Ceramic.ai_](http://%E3%83%87%E3%83%A2%E3%81%A8Ceramic.ai)[ _ドキュメント_](https://docs.ceramic.ai)で詳細をご確認ください。

### Stocktwits：株式シグナルへの支払い

>  _「エージェントはデータの消費方法を変えます。顧客がサブスクリプションを契約したり企業ライセンスを交渉したりする代わりに、エージェントが必要な時に必要なものを正確に要求できます。その個別のリクエストに課金できることで、Stocktwitsがデータを提供する全く新しい方法が開かれます。」— Howard Lindzon、創業者兼CEO、Stocktwits_

株価が動き始めたとき、トレーダーが最初に問うのは「他の人は何と言っているか」ということです。

その会話は18年間、[ _Stocktwits_](https://stocktwits.com/)で行われてきました。2008年に開始されたStocktwitsは、個別銘柄に関する市場会話を整理するためのキャッシュタグ（$[NET](https://stocktwits.com/symbol/NET)など）を生み出した先駆者です。現在、1,000万人以上がStocktwitsを使って市場を追い、アイデアを共有し、他の投資家の意見を確認しています。

Stocktwitsは投資家に特化しているため、リテール投資家が注目・議論していることをリアルタイムで把握できます。Stocktwitsはその活動をシグナルに変換します。例：

  * **センチメント：** あるティッカーに関する最近の投稿が強気か弱気かどうか
  * **メッセージ量：** あるティッカーが通常の活動と比較してどれだけの会話を生んでいるか
  * **フォロワー数：** あるティッカーをフォローしているStocktwitsユーザー数（リテール投資家の継続的関心の指標）
  * **トレンド：** どのティッカーが最も速く注目を集めているか



これらのシグナルは、Stocktwitsの既存データ製品を通じて長く提供されてきました。Monetization Gatewayは、新しいタイプの顧客向けに追加の流通チャネルを生み出します。それは、オンデマンドで市場コンテキストを必要とするAIエージェントです。例えば、ポートフォリオを監視したり投資を調査したりするエージェントが、$NET周辺の会話が活性化しているか、センチメントが強気か弱気に偏っているか、何人の投資家がそのティッカーをフォローしているかを確認できます。従来のデータライセンスは不要で、開発者はエージェントが実際に行う個別のリクエストに支払いできます。

最初に、Stocktwitsはこれらのリクエスト向けに別個のエージェント向けパスを構築し、その前面にCloudflareのMonetization Gatewayを配置しました。既存のAPIと企業向けデータ製品はそのまま変更されません。各リクエストは個別に価格設定され、Stocktwitsが既存のデータ製品とライセンスモデルを維持しながらAIエージェントへのシグナル提供を可能にします。今すぐ[ _ドキュメントから始めましょう_](https://api-docs.stocktwits.com/#tag--Monetization-Gateway-\(x402\))。

### **API2PDF：APIアクセスへの支払い**

[ _API2PDF_](https://api2pdf.com/)は、HTMLおよびOfficeドキュメントからPDFを生成するREST APIです。2018年の開始以来、API2PDFはAIエージェントが開発者を自社サービスに誘導するケースが増加しており、現在ではファーストクラスの顧客として扱っています。

API2PDFの消費ベースの価格モデルでは、各リクエストの処理に必要な帯域幅と計算リソースが顧客に請求されます。以前は、サービス利用前にアカウントの作成とAPIキーの取得が必要でした。1か月後にはクレジットカードの登録が必要となり、50%以上のコンバージョン低下をもたらしました。API2PDFは現在、Monetization Gatewayを使用して、ユーザーやエージェントがAPIキーなしでリクエストした場合にHTTP 402レスポンスを返します。各リクエストは計算・帯域幅コストが変動するため、API2PDFは変動価格を使って1回のリクエストにかかる最大コストをエージェントに伝えます。クライアントが支払いを完了すると、API2PDFはリクエストを処理し、実際の消費分のみを決済します。

エージェントは開発者と同じ「自社構築か外部調達か」の判断を迫られます。PDFが必要なエージェントは、自分でトークンを費やして生成するか、API2PDFのような専門APIに数分の一セントで依頼して適切に作成してもらうかを選択できます。
    
    
    $ curl -iX POST https://v2.api2pdf.com/chrome/pdf/html --header "Content-Type: application/json" --data '{"html":"<p>Hello from an AI agent</p>"}'
    
    HTTP/2 402
    content-type: application/json
    payment-required: eyJ4NDAy...

#### **今すぐ始めましょう**

Monetization Gatewayは、対象となる米国拠点の販売者と購入者向けにクローズドベータで提供されており、新しい地域のサポートも予定しています。製品をエージェント対応にすることに関心がある場合は、ぜひご連絡ください。[ _Cloudflare Dashboard_](https://dash.cloudflare.com/?to=/:account/monetize/monetization-gateway)でオンボーディング申請を行い、[ _Developer Docs_](https://developers.cloudflare.com/monetization-gateway)もご確認ください。折り返しご連絡いたします。ご質問やアイデアがある方、エージェント決済のスケールを支援したい方は、メールでお問い合わせください。
