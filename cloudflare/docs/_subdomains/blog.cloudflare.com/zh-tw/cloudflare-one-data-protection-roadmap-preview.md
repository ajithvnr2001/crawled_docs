今天，我們宣佈推出 Cloudflare One for Data Protection，這是一款統一套件，可保護 Web、SaaS 和私人應用程式中各處的資料。該套件融合了我們的 [Data Loss Prevention (DLP)](https://www.cloudflare.com/learning/access-management/what-is-dlp/)、[雲端存取安全性代理程式 (CASB)](https://www.cloudflare.com/learning/access-management/what-is-a-casb/)、[Zero Trust 網路存取 (ZTNA)](https://www.cloudflare.com/learning/access-management/what-is-ztna/)、[安全 Web 閘道 (SWG)](https://www.cloudflare.com/learning/access-management/what-is-a-secure-web-gateway/)、[遠端瀏覽器隔離 (RBI)](https://www.cloudflare.com/learning/access-management/what-is-browser-isolation/) 和[雲端電子郵件安全](https://www.cloudflare.com/learning/email-security/what-is-email-security/)服務等功能。該套件現已推出，並打包作為我們的 [SASE](https://www.cloudflare.com/learning/access-management/what-is-sase/) 平台 [Cloudflare One](https://www.cloudflare.com/cloudflare-one/) 的一部分。

在[公告帖文](https://blog.cloudflare.com/cloudflare-one-data-protection-roadmap-preview/)中，我們透過推薦的使用案例和真實的客戶範例，重點介紹了該資料保護套件如何幫助客戶應對現代資料風險。

在這篇配套部落格文章中，我們回顧了過去一年中內建至 Cloudflare One 套件的功能，並簡要介紹了客戶可以期待的新功能。該部落格最適合有興趣使用 Cloudflare One 保護資料和 SaaS 環境的從業者閱讀。

## 去年推出的 DLP 和 CASB 功能

Cloudflare 於 2022 年 9 月推出了 [DLP](https://blog.cloudflare.com/inline-dlp-ga/) 和 [CASB](https://blog.cloudflare.com/casb-ga/) 服務，此後快速構建了功能，以滿足各種規模的組織不斷增長的需求。在介紹這些服務將如何發展之前，有必要回顧一下過去一年中新增的許多增強功能。

Cloudflare 的 [DLP](https://blog.cloudflare.com/inline-dlp-ga/) 解決方案可幫助組織根據多個特徵偵測和保護整個環境中的敏感性資料。DLP 控制對於防止（和偵測）破壞性洩漏，並確保財務、健康和[個人識別](https://www.cloudflare.com/learning/privacy/what-is-pii/)資訊等受監管資料類別的合規性至關重要。

DLP 偵測和原則的改進可以分為三大主題：

  * ******自訂：******使管理員能夠輕鬆、靈活地設計 DLP 原則。
  * ******深度偵測：******讓管理員能夠愈加精細地控制想要保護的資料以及保護的方式。
  * ******詳細偵測：******為管理員提供更詳細的可見性和記錄，以分析其 DLP 原則的有效性。



Cloudflare 的 [CASB](https://blog.cloudflare.com/casb-ga/) 幫助組織連接、掃描和監控第三方 SaaS 應用程式是否存在設定錯誤、資料共用不當和其他安全風險——所有這些都透過輕量級 API 整合實現。透過這種方式，組織可以重新獲得對 SaaS App 不斷增長的投資的可見性和控制力。

同樣，CASB 產品增強功能也可以用三個主題來概括：

  * ******擴展 API 整合：******如今，我們的 CASB 與 [18 個最熱門的 SaaS App](https://developers.cloudflare.com/cloudflare-one/applications/scan-apps/casb-integrations/) 整合——Microsoft 365（包括 OneDrive）、Google Workspace（包括 Drive）、Salesforce、GitHub 等。與第一代 CASB 解決方案相比，設定這些 API 整合所需的點擊次數更少，覆蓋範圍與[安全服務邊緣 (SSE)](https://www.cloudflare.com/learning/access-management/security-service-edge-sse/) 領域的其他廠商相當。
  * **** **強化 CASB 掃描的結果** ：****透過儀表板中內建的規定指南和內嵌原則動作，可以更輕鬆地修復這些 CASB 掃描發現的設定錯誤。
  * ******融合 CASB 和 DLP 功能：******我們開始支援組織[掃描 SaaS App 以獲取按 DLP 原則分類的敏感性資料](https://blog.cloudflare.com/zh-tw/casb-dlp-zh-tw/)。例如，這可以幫助組織偵測信用卡或社會安全號碼出現在已向網際網路上所有人公開的 Google 文件或試算表中的情況。

## 新的和即將推出的 DLP 和 CASB 功能

今天推出的 [Cloudflare One 資料保護套件](http://cfl.re/data-protection-press-release)表明，我們一直在踐行在這些主題領域持續投資 DLP 和 CASB 功能的承諾。下面，我們將簡要介紹 Cloudflare One 資料保護套件藍圖上的一些新功能和即將推出的功能，這些功能將在未來幾週內推出，以實現跨資料環境的進一步可見性和控制。

###  _使用自訂詞表進行精確資料匹配_

**已經交付：**[Exact Data Match](https://blog.cloudflare.com/zh-tw/edm-beta-zh-tw/)，從測試版轉向全面可用，允許客戶透過上傳資料集告訴 Cloudflare 的 DLP 到底要查找哪些資料，其中可能包括姓名、電話號碼或其他任何內容。

**未來 30 天：**客戶很快將能夠上傳特定字詞清單、建立 DLP 原則以在檔案中搜尋這些重要關鍵字，以及封鎖和記錄該活動。

**客戶如何受益：**管理員可以更具體地設定他們需要保護的內容，並透過批量上傳他們最關心的資料和術語來節省建立原則的時間。隨著時間的推移，許多組織積累了為現有 DLP 服務設定的一長串術語清單，這些可自訂的上傳功能[簡化了從其他廠商遷移](https://blog.cloudflare.com/descaler-program-update/)到 Cloudflare 的過程。與所有其他 DLP 設定檔一樣，Cloudflare 在內嵌流量和整合 SaaS App 中搜尋這些自訂清單和關鍵字。

###  _偵測原始程式碼和健康資料_

**未來 30 天：**很快，Clouflare 的 DLP 將包含預先定義的設定檔，以偵測開發人員原始程式碼和[受保護的健康資訊 (PHI)](https://www.cloudflare.com/learning/privacy/what-is-hipaa-compliance/)。初時，程式碼資料將包括 Python、Javascript、Java 和 C++（當今四種最流行的語言）等語言，PHI 資料將包括藥物和診斷名稱（兩個高度敏感的醫學主題）。

**客戶如何受益：**這些預先定義的設定檔將覆蓋範圍擴大到組織內一些最有價值的資料類型（而 PHI 是最受監管的資料類型之一）。

###  _融合 API 驅動的 CASB 和 DLP 以實現待用資料保護_

**未來 30 天：**很快，組織將能夠掃描 Microsoft 365（例如 OneDrive）中待用的敏感性資料。例如，對這些環境進行基於 API 的掃描，將標記信用卡號碼、原始程式碼或透過 DLP 原則設定的其他資料是否駐留在可公開存取的檔案中。然後，管理員可以透過內嵌 CASB 閘道原則採取規定步驟進行修復。

**年底交付** ：在接下來的幾個月內，GitHub 將提供相同的整合功能。

**客戶如何受益：**利用現有的 [Google Workspace](https://developers.cloudflare.com/cloudflare-one/applications/scan-apps/casb-dlp/) 整合和即將推出的 Microsoft 365 整合，客戶可以在使用者花費大量時間以及組織儲存大量資料的兩個最知名雲端生產力套件中掃描敏感性資料。這項新的 Microsoft 整合的推出，表明我們一直在對簡化整個 Microsoft 生態系統中的安全工作流程進行持續投資——無論是[管理身分和應用程式存取](https://blog.cloudflare.com/zh-tw/expanding-our-collaboration-with-microsoft-proactive-and-automated-zero-trust-security-zh-tw/)、[執行裝置狀態](https://blog.cloudflare.com/cloudflare-microsoft-intune-partner-to-give-cisos-secure-control-across-devices-applications/)，還是[隔離有風險的使用者](https://developers.cloudflare.com/cloudflare-one/tutorials/azuread-risky-users/?cf_target_id=9878E2009FA06D9AC4B5552DD9D7E75D)。

GitHub 整合還恢復了對一個最關鍵開發人員環境的可見性，而該環境也越來越容易產生資料洩露的風險。事實上，根據 [GitGuardian](https://www.gitguardian.com/state-of-secrets-sprawl-report-2023) 的資料，2022 年 GitHub 公開提交中暴露了 1000 萬個硬編碼機密，這一數字比 2021 年增長了 67%，並且預計只會增長。防止 GitHub 上的原始程式碼暴露是我們的產品團隊經常從客戶那裡聽到的一個問題領域，我們將繼續優先考慮保護開發人員環境。

###  _Zero Trust 環境分層：使用者風險評分_

**未來 30 天：**Cloudflare 將引入風險評分，該評分將基於在 Cloudflare One 服務中偵測到的使用者行為和活動。組織將能夠偵測會帶來風險的使用者行為，例如「不可能的旅行」異常或在給定時間段內偵測到過多的 DLP 違規行為。在推出偵測功能後不久，我們將可以選擇在更廣泛的 Cloudflare One 套件中採取預防性或補救性原則動作。這樣，組織可以根據不斷變化的風險因素和即時環境來控制對敏感性資料和應用程式的存取。

**客戶如何受益：**如今，組織需要花費大量時間、人力和金錢來分析大量記錄資料以識別風險模式。Cloudflare 的「現成可用」風險評分簡化了該流程，幫助組織快速高效地瞭解並鎖定可疑活動。
