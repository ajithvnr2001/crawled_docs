วันนี้ ผมได้เข้าร่วมเป็นสมาชิกคณะกรรมการบริษัทของ Cloudflare และเกษียณจากงานประจำในตำแหน่ง CTO แล้วหลังจากอยู่กับบริษัทมานานกว่า 13 ปี 

ย้อนกลับไปในปี 2012 ผมเขียนโพสต์สั้น ๆ บนไซต์ส่วนตัวที่ตั้งชื่อง่าย ๆ ว่า: [_Programmer_](https://blog.jgc.org/2012/02/programmer.html) โพสต์นั้นประกาศว่า ผมเพิ่งเข้าร่วมงานกับบริษัทที่ชื่อว่า CloudFlare (ตอนนั้นยังใช้ "F" ตัวใหญ่เท่ ๆ) ในตำแหน่งโปรแกรมเมอร์ ผมเลือกใช้ชื่อตำแหน่งว่าโปรแกรมเมอร์ ส่วนหนึ่งเป็นเพราะว่านั่นเป็นชื่อตำแหน่งแรกสุดที่ผมเคยมี และเพราะเป็นชื่อที่สะท้อนสิ่งที่ผมทำที่ Cloudflare

ผมใช้เวลามากมายทำงานที่สตาร์ทอัปหลากหลายแห่ง ทั้งในตำแหน่งทางด้านเทคนิคและการบริหารจัดการ และต้องการกลับมาที่งานด้านเทคนิคที่ผมรักที่สุด Cloudflare มอบโอกาสนั้น และผมทำงานกับระบบต่าง ๆ ที่ประกอบขึ้นมาเป็น Cloudflare ที่ผู้คนจำนวนมากใช้กันอยู่ในทุกวันนี้

เมื่อมองย้อนกลับไปตอนที่ผมใช้เวลาอยู่กับบริษัท เป็นเรื่องยากที่จะเลือกเรื่องเด่นที่ผมเคยเขียน ในปี 2019 [_ผมเขียนบทความ 6,000 คำเกี่ยวกับประสบการณ์ในระหว่างที่ช่วยสร้าง Cloudflare_](https://blog.cloudflare.com/helping-to-build-cloudflare-part-1/) แต่ตอนนี้มีเรื่องที่โดดเด่นอยู่ 5 เรื่อง:

### ส่งมอบทันเวลาเสมอ

ค่ำคืนที่เราสรุปการเตรียมงานเปิดตัว [_Universal SSL_](https://blog.cloudflare.com/introducing-universal-ssl/) ยังคงตราตรึงในความทรงจำของผม เราเตรียมพร้อมเสนอ Universal SSL ครั้งแรกในอุตสาหกรรมแบบฟรี ๆ เพื่อขยายขนาดเว็บที่เข้ารหัสเพิ่มเป็นสองเท่าอย่างมีประสิทธิภาพในชั่วข้ามคืน ถือเป็นเรื่องใหญ่ในปี 2014 ผมจำได้ว่าผู้ก่อตั้งคนที่ 3 ของ Cloudflare คุณ Lee Holloway นั่งอยู่กับแล็ปท็อปและเขียนโค้ดจนเสร็จ ทีมทำงานกับระบบนี้มาตลอดวันสุดสัปดาห์ และกลางดึกวันอาทิตย์ Lee ก็ประกาศว่า "เสร็จแล้ว" 

### การรับมือกับความยากลำบาก

เป็นเรื่องง่ายหากจะเลือกช่วงเวลาที่เราประสบความสำเร็จอย่างยิ่งใหญ่หรือตอนที่ทุกอย่างเป็นไปด้วยดีนั้น และ [_Cloudbleed ในปี 2017_](https://blog.cloudflare.com/helping-to-build-cloudflare-part-2/) อาจไม่ใช่ช่วงเวลาพิเศษ แต่เป็นเครื่องบ่งบอกว่าเราเป็นใครได้ดี เวลาในปีนั้นแสดงให้เห็นว่าทีมสามารถอยู่ร่วมกันภายใต้ความกดดันอันหนักหน่วง และเราสามารถกำหนดมาตรฐานเพื่อก้าวไปข้างหน้าได้ด้วยการเปิดเผยและพูดคุยเกี่ยวกับปัญหาความปลอดภัยของบริษัทต่าง ๆ ตัวผมเองพบว่าการโทรผ่าน Google Meet สามารถดำเนินการได้ตลอด 24 ชั่วโมงและการเลือกงีบครั้งละ 2 ชั่วโมงก็ย่อมทำได้

### เป็นบริษัทนานาชาติและความตั้งใจ

ผมมาจากสหราชอาณาจักร และเป็นสมาชิกคนแรกในทีมที่อยู่นอกสหรัฐอเมริกา ผมได้ช่วยสร้างสำนักงานที่ใหญ่ที่สุดนอกสหรัฐอเมริกา ที่แรกคือสำนักงานสาขาลอนดอนของ Cloudflare จากนั้นคือ[ _สำนักงานสาขาลิสบอน_](https://blog.cloudflare.com/cloudflare-lisbon-office/)ของ Cloudflare สำนักงาน 2 แห่งนี้เป็นส่วนสำคัญของตัวตนของเราในทุกวันนี้ โดยที่สาขาลิสบอนเป็นสำนักงานนใหญ่ทางฝั่งยุโรปของเรา

เมื่อโควิดขัดขวางการทำงานในสำนักงาน ผมรู้สึกประท้บใจกับการตอบสนองจากทีมที่มีเข้ามามากมาย เราแต่ละคนเผชิญความยากลำบากจากการแพร่ระบาดครั้งนั้นแตกต่างกันไป แต่เรายังทำงานด้วยกันเพื่อให้แน่ใจว่าอินเทอร์เน็ตที่ทุกคนพึงพาอาศัยขณะกักตัวอยู่ที่บ้านจะทำงานได้อย่างน่าเชื่อถือและมีความปลอดภัย

### เทคโนโลยีที่สร้างแรงกระเพื่อมอย่างแท้จริง

การเลือกผลิตภัณฑ์โปรดนั้นก็เหมือนการขอให้เลือกลูกคนโปรด แต่ผมถูกใจโซลูชัน WAF, DNS และ DDoS ของ Cloudflare เป็นพิเศษ เพราะว่าผมทำงานกับระบบเหล่านั้นด้วยตัวเอง และผมยังคงรู้สึกว่าต้องขอโทษทีม WAF ที่รับช่วงต่อโค้ดของผมไป และเจอกับสคริปต์ Perl อันนั้นที่ไม่ควรเอ่ยถึง!

นอกเหนือจากผลิตภัณฑ์แล้ว ยังมีสิ่งที่ลึกซึ้งกว่านั้นนั่นก็คือ ภารกิจของ Cloudflare ในการช่วยสร้างอินเทอร์เน็ตที่ดีขึ้น ผมภาคภูมิใจมาก ๆ กับการที่เราช่วยสนับสนุนและผลักดันอินเทอร์เน็ตให้ก้าวหน้าผ่านการทำงานกับมาตรฐานและโปรโตคอลล่าสุดต่าง ๆ ของเรา และผมยิ่งภูมิใจมากขึ้นกับบทบาทที่เรามีผ่าน Project Galileo, The Athenian Project และ Cloudflare for Campaigns

### บุคลากร

ทุกสัปดาห์ Cloudflare จะจัดการประชุมบริษัทที่รวมทุกคนไว้ด้วยกัน ซึ่งปิดท้ายด้วยการ "ป่าวประกาศ" ซึ่งก็คือโอกาสแสดงความชื่นชมสมาชิกในทีมผู้ทุ่มเท ความสงสัยและความเห็นอกเห็นใจเป็นค่านิยมสำคัญ 2 ประการที่ Cloudflare และผมประหลาดใจทุกสัปดาห์ว่า เราชื่นชมทีมงานที่ได้รับคำขอบคุณจากการช่วยเหลือบ่อยเพียงใด ไม่ว่าจะในการขาย การแก้ไขบั๊ก การตอบสนองอุบัติการณ์ หรือการช่วยสร้าง Cloudflare จิตวิญญาณของการเป็นทีมนั้นเป็นส่วนหนึ่งที่ทำให้ Cloudflare เป็นสถานที่ทำงานแสนพิเศษ

สิ่งหนึ่งที่ผมจะคิดถึงเมื่อไม่ได้อยู่ที่ Cloudflare ในแต่ละวันคือจุดแข็งอันน่าทึ่งของสมาชิกในทีมแต่ละคน ผมได้เรียนรู้จากพวกเขามา 13 ปีเต็ม!

### มีอะไรใหม่บ้าง

ผมเข้าร่วมบริษัทตอนที่ทีมเล็กกว่านี้มาก! เรามีกันอยู่ 25 คน และตอนนี้ เราเติบโตจนมีพนักงานมากกว่า 4,200 คน กระจายอยู่ใน 15 แห่งทั่วโลก ขณะที่เราเติบโต ผมได้สวมบทบาทต่าง ๆ ผมได้เป็นทั้งวิศวกร ฝ่ายปฏิบัติงาน ฝ่ายความปลอดภัย และแม้แต่ IT และแน่นอนว่า ผมเขียนและแก้ไขบทความในบล็อก Cloudflare มาหลายปี เมื่อเวลาผ่านไป เราจ้างผู้นำเก่ง ๆ มากมายมาดูแลทีมเหล่านั้น

แต่บทบาทที่คงอยู่มานานคือ CTO และวันนี้ เราประกาศว่าผมต้องสละตำแหน่ง CTO (และความรับผิดชอบของตำแหน่ง) เช่นเดียวกับที่ผมสละตำแหน่งโปรแกรมเมอร์ (และการเขียนโปรแกรมที่อยู่กับตำแหน่งนั้น) เพื่อรับบทบาทใหม่เพื่อคอยช่วย Cloudflare ให้เติบโตและประสบความสำเร็จในฐานะคณะกรรมการบริษัท

ปีที่แล้วตอนที่ผมบอก Matthew ว่าผมวางแผนจะเกษียณแล้ว ผมไม่ได้คาดหวังว่าจะได้รับตำแหน่งคณะกรรมการของบริษัทเลย นั่นเป็นเกียรติสูงสุดและหาได้ยากจากการเป็นพนักงานบริษัท (ถึงแม้จะเป็นหนึ่งในกลุ่มคนที่อยู่ใกล้กับจุดเริ่มต้นมากที่สุด) แล้วได้เข้าร่วมเป็นคณะกรรมการบริษัท ผมซาบซึ้งอย่างยิ่งที่ยังสามารถช่วย Cloudflare เติบโตและประสบความสำเร็จได้จากมุมสูงขึ้นที่แตกต่างออกไป

ในขณะเดียวกัน Dane Knecht ซึ่งปัจจุบันเป็น SVP ของฝ่ายเทคโนโลยีใหม่และการบ่มเพาะ จะมาเข้ารับตำแหน่ง CTO ของเราแทน Dane มาร่วมงานเพียงไม่กี่เดือนหลังจากผม และมีบทบาทและประสบการณ์โดดเด่นไม่ซ้ำใครสำหรับการรับตำแหน่ง CTO เราทำงานกันอย่างใกล้ชิดมา 13 ปีในฐานะเพื่อนร่วมงาน บางครั้งในระหว่างการประชุมหลาย ๆ ครั้ง ก็ยากที่จะแยกบทบาทของเรา ผมแน่ใจว่าเลือด Cloudflare ของ Dane เป็นสีส้ม และผมไม่เคยเห็นเขาใส่เสื้อยืดที่ไม่มีคำว่า Cloudflare เลยสักครั้ง เราเป็นส่วนหนึ่งในทุกความก้าวหน้าที่ Cloudflare เราเอาใจใส่บริษัทและความสำเร็จของบริษัทอย่างลึกซึ้ง เขาจะเป็น CTO ที่ดีได้แน่นอน

ผมไม่ได้วางแผนที่จะหายหน้าหายตาไปทำงานที่อื่น หรือเริ่มบริษัทใหม่ ผมตั้งใจที่จะอยู่ใกล้ชิดกับ Cloudflare ในฐานะคณะกรรมการ ผมรู้สึกเป็นเกียรติอย่างสูง และซาบซึ้งที่ได้เป็นส่วนหนึ่งในการเติบโตและความสำเร็จอันยอดเยี่ยมของ Cloudflare และผมหวังว่าจะได้ช่วยให้บริษัทเติบโตต่อไป

ส่วนหนึ่งที่ผมสนใจช่วยเหลืองานของบริษัทเป็นพิเศษคือการทำงานกับชุดผลิตภัณฑ์ที่เกี่ยวข้องกับ AI ย้อนกลับไปในปี 2002 (เมื่อ 23 ปีก่อน! นานมาก!) ผมเขียนโปรแกรม[ _กรองอีเมล_](https://en.wikipedia.org/wiki/POPFile) Machine Learning (ตอนนั้นยังไม่ได้เรียกว่า AI) แบบโอเพ่นซอร์สขึ้นมา และในปี 2004 ผมได้ช่วยทำงานเพื่อรับมือกับสิ่งที่เกิดขึ้นเมื่อ[ _ระบบ AI หนึ่งถูกนำมาใช้เพื่อโจมตีระบบอื่น_](https://blog.jgc.org/2023/07/how-to-beat-adaptivebayesian-spam.html) ที่ Cloudflare เราใช้เทคนิคการเรียนรู้เพื่อเพิ่มความปลอดภัย บล็อกบอท และคาดการณ์ว่าระบบของเราควรมีพฤติกรรมและเติบโตอย่างไร ยังมีสิ่งที่ต้องทำอีกมากมาย
