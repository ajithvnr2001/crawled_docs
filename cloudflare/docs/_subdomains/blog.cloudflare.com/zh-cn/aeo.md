# 从排名到获得推荐：让您的站点在 AI 智能体时代蓬勃发展

![Matthew Conroy](https://blog.cloudflare.com/_image?href=https%3A%2F%2Fblog.cloudflare.com%2F_emdash%2Fapi%2Fmedia%2Ffile%2F01KWW2PW1QZW47KMHA09RY62FC.jpg&w=64&h=64&f=webp&fit=cover&position=center)![Jack Galilee](https://blog.cloudflare.com/_image?href=https%3A%2F%2Fblog.cloudflare.com%2F_emdash%2Fapi%2Fmedia%2Ffile%2F01KZA3MX64PMX25X6GHJWTCKYT.jpg&w=64&h=64&f=webp&fit=cover&position=center)

您的下一位客户或许不会通过搜索引擎找到您。取而代之，他们会向 AI 助手提问：“我该如何完成 X？”、“哪一种方案最适合我这类用户？”、“直接帮我处理这件事”；随后智能体会查找答案、权衡各个选项，并代表用户执行操作。决定客户是否选择您的关键时刻越来越多地发生在模型输出的响应结果内部，此时用户甚至尚未访问过您的主页。

智能体受众时代已经到来：根据我们的统计，所有 HTML 页面请求中，[​ _目前来自人类_](https://radar.cloudflare.com/traffic#bot-vs-human)的不到一半。并非所有这类机器流量都是代表人类行事的智能体，但该部分占比正快速增长；答案引擎、购物助手与调研工具将决定哪些企业能够被检索到并获得推荐。过去，可发现性是指是结果页面上的排名。如今，它指的是被引导您客户的智能体找到、读取并得到可靠推荐。

旧有指标，即人类点击量与页面浏览量，不再反映全部实际情况。我们与众多网站所有者进行了交流，他们查看充斥 AI 机器人的访问日志，却完全无从知晓这些机器人能否正常使用其网站，也不知道它们会不会向用户推荐其产品与服务。我们听到了两个主要问题：

  * 智能体实际上能不能使用我的网站？
  * 我的网站得到推荐了吗？



为帮助网站所有者解答上述问题，我们已将在 Agent Readiness 方面的[​ _工作成果_](https://blog.cloudflare.com/agent-readiness/)集成至 Cloudflare 仪表板，同时增加了新的 Answer Engine Optimization（AEO）工具。这些工具将智能体视为网站的核心用户群体，向您展示智能体将如何解析您的站点，以及您获得推荐的频次。

机遇巨大，门槛不高，因为绝大多数网站尚未针对这一用户而设计。正如早期搜索引擎优化（SEO）会奖励为搜索引擎而搭建的网站，如今为智能体打造的网站也将获得相应红利。易于查找、阅读和信赖的信息才会得到智能体的推荐。

## **Diagnostics：您的网站是否已做好智能体适配？**

Diagnostics 是 Agent Readiness 中的技术检查工具。它以智能体读取网站的方式扫描您的站点：判断是否允许其访问、能否发现您的内容，获取一份干净的机器可读副本，并查找可供调用的接口。 

人类用户只加载您的主页，而智能体会依赖站点的 robots.txt 、站点地图、响应头、内容的 Markdown 版本，以及用于身份验证与工具集成的已发布元数据。

Diagnostics 对某个主机名执行这些检查，并将结果汇总到一个 agent-readiness 视图中：从‘Not Ready’（未就绪）到 ‘fully agent-native’（完全智能体原生）。每项检查返回的结果为通过、失败或中性，附带说明解释其意义；同时提供一条证据链，展示精确请求与所收到的响应。

检查结果按工作量分组，让您知道从哪里开始：

  * 快速见效项：多数站点尚未配置的高价值基础能力，包括可供爬虫读取的 robots.txt 、XML sitemap 、AI 爬虫规则，以及向智能体输出规整的 Markdown。
  * 技术基础工作：下一层，包括指明站点内容使用方式的 Content Signals，API 目录，链接头，以及智能体登录指引
  * 高级集成：智能体原生功能，包括 OAuth 发现、MCP（Model Context Protocol）与 A2A（Agent2Agent）智能体卡片、技能索引、Web Bot Auth 及 WebMCP。
  * 商业：新兴智能体支付标准，包括 [​ _x402_](https://blog.cloudflare.com/x402/)（经典 HTTP 402 Payment Required 状态码的扩展）、ACP（智能体商业协议）、通用商业协议（UCP）以及 AP2（智能体支付协议）。该内容目前仅作信息展示，不计入您的得分。

每一项建议的优化项均附有后续操作步骤。如果有可提供帮助的 Cloudflare 功能，则会显示 “在 Cloudflare 中设置” 链接，直接跳转至对应配置项，例如为智能体开启 Markdown 功能或使用托管式 robots.txt。对于其他所有情况，您可以使用“复制智能体提示词”按钮，即可获取有关编码智能体所需构建内容的建议。完成修改，重新扫描，观察检测复选标记变为绿色。

## **AEO：AI 助手有没有推荐您的站点？**

Diagnostics 检查智能体能否读取您的网站。AEO 标签告诉您接下来会发生什么：当客户就您所属类别向 AI 助手提出问题时，AI 助手会推荐您的站点，还是推荐竞争对手的站点？这一点无法像搜索排名那样查询。没有曝光量统计，也没有漏点击报告。因此，当 AI 助手推荐竞争对手而非您的站点时，商机就会流失，而且您毫不知情。

![](data:image/bmp;base64,Qk32BAAAAAAAADYAAAAoAAAACAAAAAgAAAABABgAAAAAAMAAAAATCwAAEwsAAAAAAAAAAAAA+fbz9fLw7uvs6ejp6urp6Ovn4OXd09rR+/n19/Xz7+3u6+rr7Ozs7O7q5Oji2N7X/v36+vj38fDx7ezu7+/v8PLv6u3o3+Pe///+/Pz78/P17+/x8vLz9fXz7/Hu5ejl/////v/+9fb48fL09PX2+Pj38/Xy6evq////////9/j68/P39vf4+fr59fb16+3t////////+Pn89fT49/j6+vv69vf27O7u////////+fn99fX5+Pj6+vv79vj27O7u)![BLOG-3440 4.png](https://blog.cloudflare.com/_image?href=https%3A%2F%2Fblog.cloudflare.com%2F_emdash%2Fapi%2Fmedia%2Ffile%2F01KZA2SCHB021NKDSW68C9X8SR.png&w=715&h=720&f=webp&fit=cover&position=center)

我们会从您的网站推断出您所属的行业（例如健康与健身）及业务类别（例如运动服饰），并使用客户可能输入的提示词，对主流 AI 助手（目前为 Anthropic 的 Claude 和 OpenAI 的 GPT）发起问询，查看它们的返回结果。我们构建这些提示词以模拟现实世界的发现，在您所属类别内提出推荐、产品对比以及通用咨询请求。通过观察模型如何应答这些符合实际的查询，您可以获取以下指标：

  * **引用率：** 在您所属类别，将您的站点列为信息来源的回答占比
  * **突出性：** 当您的站点被引用时，您的内容在 AI 回答中的实际占比，以及出现位置的先后顺序
  * **提及率：** 助手在其回答中提到您的品牌的频率——例如，“Cloudflare”在响应中出现的频率，不论[ _cloudflare.com_](http://cloudflare.com) 是否被引用为来源。请结合您的引用率一同解读，该指标可区分认知度与来源归因：AI 助手对您的提及次数远高于引用次数，代表您已进入其检索视野，但尚未获得来源引用，这是一个具体、可针对性优化的短板。
  * **声音份额：** 您的引用率与竞争对手对比，从而展示谁在这些提示词中胜过您。



为了评估 AI 模型如何感知您的市场存在，我们会在对特定网站评分之前，为每个行业和类别建立一个基准。我们使用该业务类别下的常见提示词向 AI 助手发起查询，但不指定您的品牌，并记录被引用的站点、站点的出现位置以及内容的突出程度。

我们并非在站点所有者每次执行扫描时都重新向模型发起查询，而是对每个类别运行一次面板操作，并将基线复用于该领域的所有账户。预先计算该数据集有三大优势：

  * **零延迟：** 结果即刻从快照加载，而无需等待实时模型查询。
  * **降低计算开销：** 在类别级别聚合查询可避免数千次扫描中产生的重复 AI 调用。
  * **行业契合度评分：** 复用面板语料库，我们能够梳理出哪些品牌会始终一同出现，进而得出行业契合度分数，衡量 AI 助手是否会将您的站点与您的真实竞争对手归为一类。



AI 助手很少会两次以完全相同的方式回答同一个问题。为了处理这种差异，我们使用 [  _Cloudflare AI Gateway_](https://www.cloudflare.com/products/ai-gateway/) 向每个助手发出多次使用不同模型的查询。然后，我们阅读客户会看到的响应——答案文本及每个助手引用的来源——并从中提取多个信号。 

我们不仅评估您的站点是否被提及，还会评估您是否被作为信息来源引用、您的引用内容在回答中出现的先后位置，以及最终回答中有多少实质内容源自您的站点。在需要真正判断力的情况下，Workers AI 会执行繁重的任务，在我们自有基础设施上原生运行，读取每个回复并对您的引用和提及出现的情况进行评分。我们还采用精确文本分析，而非由模型对自身输出进行评分。综合以上处理，数十条一次性返回结果被整合为可执行操作的指标。该工具通过抽象多模型查询与评估流水线来输出各项指标，无需您构建自己的评估框架。

除回答外，一个 AI Operator Activity 工具还会按运营商（OpenAI 、Google 等）展示您站点上真实的爬取流量与引荐流量：谁读取了您的内容、谁为您推荐访问者，以及这个过程中遇到的各类错误（403 拦截、404 失效链接）。值得重点关注情况是：某运营商爬取您的数千个页面，却未带来任何引荐访客，即取用您的内容但不带来客户。

由于这些指标特定于您的网站，您可以进行实验，重新运行扫描，并衡量对那些可为您带来业务的具体问题的影响。

## **触达您的另一类受众**

在此之前，评估智能体访问情况需要依靠猜测：通过 grep 检索日志推断访问主体，或者向聊天机器人输入提示词，凭肉眼观察其是否提及您的站点。如今，借助 Agent Readiness 和 AEO，您可以获得采取行动所需的数据。而且，由于这些请求是实际通过 Cloudflare 传递的，这些工具均尽量采取测量而非估算的方法，并会随时间持续改进。 

帮助您了解谁正在访问您的网站，并决定如何以自己的方式进行互动，这一直是我们所做的工作。智能体只是最新的一类受众，而让智能体更容易找到、理解和信任，就能得到推荐。Agent Readiness 可以帮助判断您的站点是否达到这一状态，否则又应当采取什么措施。

准备好查明 AI 智能体是否正在为您带来客户了吗？在仪表板中转到“概览（Overview）”选项卡，让您的站点达到 Agent Ready 状态，并申请提前体验 AEO Visibility。
