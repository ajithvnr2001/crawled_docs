Agents Week 的开端，Rita [_标识_](https://blog.cloudflare.com/agents-week-welcome/)，智能体代表了计算技术的下一次进化：它不仅是 AI 的一种全新应用，更是一种全新软件品类，正在重塑人们与技术的交互方式，以及软件与互联网的交互模式。在[​ _过去一年左右的时间里_](https://www.cloudflare.com/innovation-week/ai-week-2025/updates/)，我们着手探索这一转变对构建 AI 原生应用及支持这些应用所需基础设施的开发人员和客户意味着什么。随着智能体能力和自主性不断增强，挑战已经不再局限于模型本身，而是进一步延伸至身份、通信、编排、记忆、可观测性以及安全等方面。

在过去一周里，我们分享了如何在 Cloudflare 平台上将这些能力整合起来，以服务于智能体式互联网。每天我们都展示了新的工具、产品和想法，用于构建一个人类和智能体在其中[​ _协作而非冲突_](https://blog.cloudflare.com/the-agentic-internet/)的互联网。

### **8 月 3 日（星期一）**

聚焦于构建和运行智能、自主应用的基础，也就是智能体所依赖的运行时与基础设施。

[ _您的智能体需要计算机，而不是容器—— @cloudflare/computer 发布_](https://blog.cloudflare.com/zh-cn/cloudflare-computer/)|  @cloudflare/computer 提供一种新的运行时，专为智能体设计，可以为任务选择合适的环境。  
---|---  
[ _Workers RPC 现已支持 Python 和 JavaScript 跨语言调用_](https://blog.cloudflare.com/python-workers-rpc/)|  Python 和 JavaScript Workers 现在可以直接互相通信，使混合语言项目开发更轻松。  
[ _更小、更快、更安全：大规模运行 Kimi 和 GLM_](https://blog.cloudflare.com/smaller-faster-safer-models/)|  探索如何在不牺牲质量、可靠性和安全性的情况下，更高效地提供大型模型。  
[ _推出 Billable Usage API：Cloudflare 的程序化成本可见性_](https://blog.cloudflare.com/zh-cn/billable-usage-api/)|  一种更简单的方式，跟踪我们的自助产品的使用情况和成本。   
[ _Cloudflare Workers 和容器现已支持入站 TCP 连接和 gRPC_](https://blog.cloudflare.com/grpc-workers/)|  使用 Cloudflare Workers 托管语音 AI 后端或其他实时语音智能体。  
  
### **8 月 4 日（星期二）**

推出智能体开发生命周期（ADLC）以及将智能体软件从原型推进到生产的原语。

[ _Cloudflare 现已上线 Agent Development Lifecycle（智能体开发生命周期）_](https://blog.cloudflare.com/zh-cn/agent-development-lifecycle/)|  以 ADLC 取代 SDLC（软件开发生命周期）；我们有关智能体从原型到生产的实践路线 ，以及支持下一代“软件工厂”的原语。  
---|---  
[ _隆重推出：Cloudflare Agents_](https://blog.cloudflare.com/agents-on-cloudflare/)|  在 Cloudflare 上构建代理，并实时观测每一次运行；针对生产环境中的执行事件，支持链路追踪、执行回放以及人在回路审批。  
[ _您的智能体现在可以通过本地追踪调试 Workers_](https://blog.cloudflare.com/local-tracing/)|  将分布式追踪引入本地开发环境，让智能体更容易在生产环境受影响之前找到并调试问题。  
[ _Cloudflare Wallets 正式发布：为智能体式互联网打造的可编程钱包_](https://blog.cloudflare.com/zh-cn/wallets/)|  钱包提供了一种安全的方式，让智能体作为新兴智能体经济体系中的参与方来执行交易。  
[ _在您的平台和 Cloudflare 上为数百万个代码仓库运行 CI/CD_](https://blog.cloudflare.com/ci-workflows/)|  可编程 CI/CD；通过编写代码而非配置文件来运行流水线，并由一个智能体修复失败，并提交修复后的变更以供审查。  
[ _Cloudflare 如何利用 AI 落实工程规范_](https://blog.cloudflare.com/engineering-standards-enforcement/)|  我们如何在整个开发工作流中运用 AI 驱动的自动化，确保代码规范与流程保持一致，助力我们自己的软件工厂大规模产出高质量、风格统一的代码。  
[ _我们如何建立一个软件工厂，将 Astro 的 GitHub 问题数量降至零_](https://blog.cloudflare.com/astro-issue-triage/)|  自动化问题的分析、分类和路由，以最大限度减少软件维护的繁琐工作并最大限度提高开发人员的生产力。  
  
### **8 月 5 日（星期三）**

将 Zero Trust 从用户和设备扩展到智能体本身，并为介绍其在 Cloudflare 内部如何运行。

[ _智能体访问模型_](https://blog.cloudflare.com/the-agent-access-model/)|  一套框架，用于规定智能体如何代表您安全访问各类资源与服务，适配智能体数量日益增长的互联网环境。   
---|---  
[ _我们如何借助 Cloudflare OS 重新定义 Cloudflare 内部的工作方式_](https://blog.cloudflare.com/how-we-use-ai-with-cloudflare-os/)|  我们如何在内部运营模型中嵌入 AI，让团队能够更智能、更高效地工作，同时又不牺牲安全性或监督。  
[ _Cloudflare OS：面向智能体、应用和工作的开放平台_](https://blog.cloudflare.com/zh-cn/cloudflare-os/)|  我们开源了自己内部团队用来构建应用、自动化工作以及安全访问内部系统的平台。   
[ _利用身份感知分析检测异常 AI 行为_](https://blog.cloudflare.com/zh-cn/identity-aware-ai-gateway/)|  将 AI 活动归因于真实用户和系统，更容易发现异常和费用激增。  
[ _WriteGuard：针对 MCP 服务器的细粒度管控_](https://blog.cloudflare.com/mcp-portal-writeguard-private-beta/)|  向客户提供我们内部部署到相同工具集，用于增强对高风险工具调用的管控，降低智能体产生非预期更改的机会。  
  
### **8 月 6 日（星期四）**

定义智能体式互联网，以及网站所有者、内容发布者与智能体如何共同打造一个为人类和智能体服务的互联网。

[ _构建开放的智能体式互联网：可读、可发现、可调用、可支付_](https://blog.cloudflare.com/zh-cn/the-agentic-internet/)|  一种智能体式互联网模式，其中内容发布者维持控制权，智能体以有效方式访问所需内容；以及支持双方进行交易的开放协议。  
---|---  
[ _为任何网站提供 WebMCP 接口_](https://blog.cloudflare.com/webmcp/)|  WebMCP 的预览版推出一种全新（且非常简单）的方法，使网站和 Web 应用可以被智能体发现和使用。  
[ _从排名到获得推荐：让您的站点在 AI 智能体时代蓬勃发展_](https://blog.cloudflare.com/zh-cn/aeo/)|  将 SEO 调整为 AEO（答案引擎优化），以优化智能体发现、理解和呈现 Web 内容的方式。  
[ _推出 Kitesurf：智能体优先的浏览器，在 Cloudflare Workers 上的 V8 隔离环境中运行_](https://blog.cloudflare.com/kitesurf/)|  专为智能体打造的浏览器，放弃像素级精确渲染以降低内容占用和 CPU 使用率。  
[ _下一代 MCP_](https://blog.cloudflare.com/mcp-v2/)|  MCP 进行了重写。MCPv2 带来 MCP 支持的下一代演进，简化智能体应用的部署流程并提升其可扩展性。  
[ _Cloudflare AI Search：为您的智能体提供一个数据搜索引擎_](https://blog.cloudflare.com/ai-search-easier/)|  AI Search 通过一条命令即可将您的文件或网站转换为可供智能体调用的搜索引擎。  
  
### **8 月 7 日（星期五）**

聚焦实际发生的一切：智能体到底在 Web 上做什么，AI 在您应用中的运行位置，哪些参与者在为生态系统做出共享，以及用于分析互联网数据的全新工具。

[ _揭示智能体式互联网上的良性/不良行为_](https://blog.cloudflare.com/zh-cn/good-and-bad-agentic-behaviors/)|  机器人并不总是坏的，人类也未必总是好的；应将机器人缓解从一次性风险调整为持续信任。  
---|---  
[ _将 Workers AI 和 AI Gateway 统一在单一 AI 控制平面上_](https://blog.cloudflare.com/workers-ai-gateway-unification/)|  一个绑定、一个钱包、一个仪表板即可调用任何 AI 模型；下一步是以模型为先的路由。  
[ _宣布 Cloudflare 大使、社区工程师及额外的 100 万美元开源资金_](https://blog.cloudflare.com/community-program-refresh/)|  我们更新版社区倡议推出了两个新项目——面向社区领袖的 Cloudflare 大使与面向开源维护者的社区工程师——并将在未来两年内增加 100 万美元的开源资金。  
[ _推出 Radar Researcher：一款使用通俗语言探索互联网数据的 AI 工具_](https://blog.cloudflare.com/introducing-radar-researcher/)|  Radar 的 AI 研究助手：输入通俗语言提问，输出真正可交互的图表。  
  
### **Agents Week 已经结束，但我们继续前行**

五天后，Rita 关于“[ _智能体对智能体云有什么需求？_](https://blog.cloudflare.com/agents-week-welcome/)”这个问题的答案开始显现。它需要一个执行层和原语以便运行，一个不断自我编写的发展生命周期，为进行工作的人和智能体提供安全访问，一个智能体式互联网，以及让这一切始终脚踏实地的人类与社区。未来虽然仍有许多未知，但其形态正变得更加明朗：一个原生支持其为之构建的人类以及代表人类行事的智能体的互联网。

我们的工作不会止步于此。请留意我们的[ _更新日志_](https://developers.cloudflare.com/changelog/)以获取最新信息。如果您正在和我们一起构建这个体系的任何部分，欢迎与我们交流。请通过 [_X_](https://x.com/cloudflaredev)或[ _Discord_](https://discord.com/invite/cloudflaredev) 联系我们。
